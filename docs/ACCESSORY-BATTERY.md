# Accessory Battery — исследование и контракт 0.5.6

Основа — `aab4517`, ветка `feature/accessory-battery`. Рабочая Release 0.5.5 сохранена локально для отката. Ниже нет реальных Bluetooth-адресов, хешей выбранных устройств или серийных номеров.

## Фактические источники на этом Mac

macOS 15.7.3, Apple Silicon. Проверены именно `system_profiler SPBluetoothDataType -json` и `ioreg -r -l -k BatteryPercent`; для runtime используется plist-вывод второго через дополнительный флаг `-a`.

| Устройство / компонент | Что реально получено | Подтверждение |
|---|---|---|
| AirPods Pro, L/R | Сначала 100/100%, позднее 99/98% | После настоящего подключения IOBluetooth подтвердил соединение, адрес записи совпал точно. macOS показала 100%, затем 98%. Новые чтения показали изменение L/R, а не только успешный запуск команды. |
| AirPods Pro, общий заряд | Отдельного поля нет | Не записывается вымышленный общий процент. Ambient показывает меньший из L/R; Workspace сохраняет отдельные значения. |
| Кейс | В profiler есть 74%, **в Forelock не используется** | Запись имеет другой адрес, нет подтверждённой связи с подключёнными наушниками. Одинаковое имя не является идентичностью. При закрытии/отключении запись осталась в кэше. |
| Magic Mouse | 24% из IORegistry | Активное IOBluetooth-соединение и точное совпадение адресов; системные настройки Bluetooth тоже показали 24%. В profiler процента мыши нет. |
| Magic Keyboard / Trackpad | На текущем Mac не подтверждено | Есть неподключённые устройства, но процент не запрашивается и не изображается текущим. HID-путь реализован; поддержку конкретных моделей без живой проверки не заявляем. |
| Другие аксессуары | Не подтверждено | Только при наличии корректных полей, точной идентичности и живого подключения; специальных протоколов устройств нет. |

После физического отключения AirPods пользователь подтвердил состояние, macOS показала «Не подключено», IOBluetooth оставил только мышь. Однако profiler продолжал выводить старые AirPods 100/100 и кейс 74% в `device_connected`. После повторного подключения появилась отдельная запись с адресом настоящих наушников и L/R. Это конкретный воспроизведённый случай, почему одной категории profiler недостаточно.

## Изученный исходный код и публичные API

[MacSweep ConnectedDevice.swift, ревизия 0d3e2bff165ec52f05203ac6757bd84f793bd8f0](https://github.com/VincentShipsIt/macsweep.dev/blob/0d3e2bff165ec52f05203ac6757bd84f793bd8f0/MacSweep/Sources/Core/Monitoring/ConnectedDevice.swift) объединяет profiler и IORegistry по нормализованному адресу. В исследованной реализации ноль исключается, значения выше 100 ограничиваются, IORegistry-only запись может появиться без отдельного live-подтверждения. Эти решения не перенесены. Реализация Forelock независимая, новой зависимости или скопированного модуля нет.

В публичном SDK Xcode 16.3 у [IOBluetoothDevice](https://developer.apple.com/documentation/iobluetooth/iobluetoothdevice) проверены paired devices, address, isConnected, connect/disconnect notifications. Публичного свойства процентов AirPods L/R/Case в этом интерфейсе не найдено. `IOBluetoothHandsFreeDevice` документирует индикатор батареи 0–5 для hands-free профиля; он не используется как точный заряд AirPods. Приватные категории/селекторы не вызывались.

Публичный [CBCentralManager](https://developer.apple.com/documentation/corebluetooth/cbcentralmanager) используется только для готовности Bluetooth/разрешения. Нет сканирования, соединений GATT, сопряжения или чтения соседних BLE-устройств. На одной из реальных переустановок синхронная инициализация IOBluetooth заблокировала main. Поэтому первая регистрация вынесена с main и отложена до публичного callback готовности; после неизвестного состояния на main не выполняется `pairedDevices`. Изменение существующего AudioDeviceMonitor ограничено этим необходимым исправлением запуска.

## Достоверность и срок действия

- Объединение только по строгому нормализованному адресу. UI/постоянный выбор используют локальный непрозрачный токен; адрес не отображается и не передаётся.
- Соединение независимо читается до и после команд. Новое/исчезнувшее за время чтения устройство не наследует проценты. Callback смены соединения инвалидирует прежний epoch и поздний результат процесса.
- Настоящий 0% сохраняется. Bool, дробные, отрицательные, >100, неизвестные строки и конфликтующие значения дают недоступность. У неоднозначных записей нет выбора «первый победил».
- Отдельные L/R/Case показываются только из записи с точной идентичностью; кейс не присоединяется по имени. Отключённые устройства исключаются, выбранный недоступный аксессуар не заполняет Ambient.
- Снимок имеет время чтения macOS и TTL 90 секунд. При ошибке/тайм-ауте поля очищаются; независимый deadline убирает старые клетки даже при зависшем следующем процессе.
- **Время аппаратного измерения эти источники не дают.** Успешное повторное чтение не доказывает новое измерение самого аккумулятора. UI/help прямо называет данные сообщёнными macOS и показывает время получения; совпадение с системным UI и наблюдавшееся изменение проверены для устройств выше. Абсолютную гарантию аппаратной свежести между обновлениями системного кэша не обещаем.

## Интеграция

`AccessoryBatteryMonitor` — отдельный источник существующего DeviceEventAdapter. При подключении/смене выхода свежий заряд дополняет уже существующий Stretch; дополнительных событий на каждый процент нет. Для route связь проверяется по публичному Core Audio UID: на этом Mac подтверждён точный адрес с суффиксом `:output`. Иные форматы отвергаются, поиска по подстроке/имени нет. Заряд передаётся отдельным типизированным полем события, а не парсится из пользовательского названия.

Параметры приоритетов, TTL, дедупликации и вытеснения Live Surface сохранены. Добавлены только opt-in категория/слот аксессуара и ограниченное поле payload. По умолчанию Auto не занят батареями аксессуаров. В настройках выбирается устройство и слот «Заряд аксессуара». Workspace показывает компактный прокручиваемый список в прежнем размере панели, геометрия и motion 0.5.5 сохранены. Предупреждения низкого заряда аксессуаров не включены: физическая проверка порогов отсутствует.

## Производительность и завершение

Проверка запускается системным событием, с debounce 250 ms; повторное чтение — раз в 60 секунд только при наличии устройств. Нет опроса каждую секунду. Все команды и получение соединений выполняются на utility queue. Для каждого процесса watchdog 6 секунд, максимум stdout 2 MiB, stderr не сохраняется. При отмене/закрытии приложения текущий дочерний процесс завершается и ожидается; generation guard отбрасывает поздний результат. Сырые данные и история процентов в продукте на диск не записываются.

На этом Mac profiler занял около 0,07–0,09 s wall, 0,03–0,04 s user+sys, IORegistry около 0,01 s wall. Полный нативный проход в тесте — 0,16–0,29 s wall. Это не обещание той же скорости на других Mac; watchdog обязателен. При минутном интервале измеренное командное CPU-время соответствует оценке менее 0,1% одного ядра в среднем; это оценка для дочерних команд, не CPU всего Forelock.
