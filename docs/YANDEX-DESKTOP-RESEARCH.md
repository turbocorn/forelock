# Яндекс Музыка desktop — архив исследования публичного AX

Это исторический отчёт до отдельно разрешённой диагностики MediaRemote. Его вывод о невыпущенной версии относится к AX-эксперименту. Текущая локальная 0.4.1 использует другой подход: [изолированный MediaRemote helper](YANDEX-DESKTOP-EXPERIMENT.md). Условия и результаты ниже сохранены как история исследования.

**Результат: релиз 0.4.1 не выпущен.** На macOS 15.7.3 с Яндекс Музыкой 5.126.1 (`ru.yandex.desktop.music`) удалось читать и адресовать её AX-плеер, но не подтвердить достоверное состояние при фоновой работе. Экспериментальный провайдер не включён. Установленный Forelock остаётся **0.4.0 (40)**; его исходники, геометрия, музыкальные провайдеры и файловая полка сохранены. Исследование проведено 8 ноября 2026 на настоящем Mac, без OCR и координатных кликов.

## Accessibility: что действительно найдено

Исследованы два интерфейса: «Моя волна» и обычный нижний плеер в «Коллекции». Запросы ограничивались PID уже работающего Яндекса; применялись `AXUIElementCopyAttributeValue`, `AXUIElementCopyActionNames`, `AXUIElementIsAttributeSettable`, `AXUIElementPerformAction`, AXObserver. Новый доступ Forelock к Accessibility не запрашивался: исследовательский процесс использовал уже имеющееся разрешение инструмента.

| Поле / действие | Фактическое наблюдение |
| --- | --- |
| Трек | В нижнем плеере — AXLink с описанием `Трек …` и URL с trackId. В «Моей волне» — AXStaticText рядом с ползунком. |
| Исполнители | Отдельные ссылки `Артист …`; в «Моей волне» — подписанное меню исполнителей. Например, «Если бы» / Баста, GUF. |
| Альбом | В «Моей волне» доступна подпись `Альбом Баста / Гуф`; в проверенном нижнем плеере альбом отдельно не отдавался. |
| Обложка | В исследованных AX-плеерах нет доступного изображения или HTTPS URL обложки. Возрастная маркировка AXImage не является обложкой. |
| Playing / Paused | По кнопке `Пауза` / `Воспроизведение`, только пока дерево актуально. В фоне обнаружено расхождение с реальным состоянием. |
| Позиция / длительность | Числовые AXValue / AXMaxValue ползунка: например, 87 / 326 секунд. При скрытии значение замерзает. |
| Play / Pause | Кнопки объявляют AXPress. Реальная пауза независимо подтверждена системным плеером, но обновление AX-состояния не оказалось надёжным. |
| Previous / Next | Именованные кнопки с AXPress найдены. Next исследован, но полный цикл подтверждения в фоне не пройден; обе команды не объявляются поддерживаемыми в Forelock. |
| Seek | AXValue объявлен записываемым. Реальная перемотка через Forelock не проверена и не включена. |

### Почему пробный провайдер отклонён

1. Непрерывный опрос с AXObserver: при видимом неактивном окне позиция шла **131 → 132 → 133**. После скрытия (`isHidden = true`) она оставалась **134** до конца двадцатисекундного наблюдения. При последующем показе окна обнаруживался уже другой реальный трек.
2. После AX-паузы трека **God Is A Weapon — Falling In Reverse, Marilyn Manson** приложение возвращало старую кнопку `Пауза` и позицию 100. Независимый Control Center показывал **`воспроизвести` / `play.fill`**, то есть настоящую паузу. Код успеха AXPress не подтверждает результат команды.
3. Пробный `YandexDesktopMusicProvider` с ограниченным обходом, проверкой видимости окна и подтверждением команд воспроизвёл проблему и в обычном AppKit run loop: команда не подтверждалась, данные замирали. Проверка «Playing без движения позиции» через три секунды убирала источник, но не решала ошибку достоверности. Простого `isHidden == false` недостаточно.

Документированный Electron [AXManualAccessibility](https://www.electronjs.org/docs/latest/tutorial/accessibility) и подписка AXObserver не устранили проблему. [Electron описывает](https://www.electronjs.org/docs/latest/api/browser-window#page-visibility) скрытие, минимизацию и полное перекрытие окна как состояния page visibility на macOS. Это согласуется с наблюдениями, но точная внутренняя причина заморозки Яндекса не доказана.

Пробный запрос дополнительного атрибута `AXEnhancedUserInterface` вернул -25208; он не имеет требуемого публичного контракта и в продукт не включён. Исходное значение 0 восстановлено и прочитано обратно. Изменений системной защиты не было.

Смена Spaces отдельно не подтверждена. Завершение приложения также не выдано за успешную проверку: после отправки Quit процесс продолжал работать. Эти пункты не закрываются синтетическими тестами.

## System Now Playing

Через AX системного процесса прочитаны настоящие данные: обложка как AXImage, строка с треком, исполнителями и альбомом, кнопки play/pause/next; в раскрытом поповере — previous и тайминги, например **02:41 / 03:36**. AXURL элемента обложки пуст; чтение её байтов через публичный AX не подтверждено. Ползунок в поповере не дал проверенного адресного механизма seek.

Публичный [MPNowPlayingInfoCenter](https://developer.apple.com/documentation/mediaplayer/mpnowplayinginfocenter) описывает данные, публикуемые **самим приложением**. В отдельном процессе его `nowPlayingInfo` вернул nil во время воспроизведения Яндекса. [MPRemoteCommandCenter](https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter) регистрирует обработчики входящих команд своего приложения; это не публичный контроллер чужого PID.

AX системных кнопок технически доступен при открытой панели, но относится к текущему системному плееру. Надёжной привязки к выбранному источнику Forelock здесь не установлено. Поддерживать системный поповер открытым и разбирать его визуальную композицию — неустойчивая основа интеграции; в Forelock это не внедрялось.

## MediaRemote и распространение

[ungive/mediaremote-adapter](https://github.com/ungive/mediaremote-adapter) заявляет работу на macOS 15.4+: системный `/usr/bin/perl` динамически загружает helper, использующий приватный MediaRemote. Совместимость именно с этим Mac и Яндексом **не проверена**: код только прочитан, не собран и не запущен. Заявлены метаданные, обложка, тайминги и команды; это не гарантия локальной работоспособности.

В [adapter_send](https://github.com/ungive/mediaremote-adapter/blob/master/src/adapter/send.m) используется глобальный `sendCommand(commandValue, nil)`, а не выбранный bundle ID/PID. Адресацию нескольких плееров придётся исследовать отдельно. [Boring Notch](https://github.com/TheBoredTeam/boring.notch) прямо указывает MediaRemoteAdapter как источник Now Playing на 15.4+; это пример практики, а не подтверждение публичности API.

Риски: изменение приватного протокола или доступности системного Perl после обновления macOS, сопровождение helper и зависимость от привилегированного platform binary. BSD-3-Clause допускает распространение при соблюдении лицензии, но не делает API поддерживаемым Apple. Для App Store действует требование [публичных API, §2.5.1](https://developer.apple.com/app-store/review/guidelines/#software-requirements). Отдельное распространение, подпись и notarization требуют самостоятельной проверки; успех не обещается.

## Рекомендация и согласование

Для полноценного фонового desktop-плеера следующий обоснованный эксперимент — **отдельно согласованный диагностический запуск MediaRemote Adapter**, сначала вне Forelock: метаданные, обложка, тайминги, команды, точная идентификация и адресация источника. Это требует явного согласия на приватный API и схему с системным Perl. Отключение SIP, изменение entitlement и инъекции в Яндекс не предлагаются.

Если остаёмся исключительно на публичных механизмах, рекомендую сохранить работающий Chrome Bridge и запросить поддерживаемый интерфейс у Яндекса. Ограниченный AX-плеер с требованием держать окно доступным можно рассматривать только как отдельный эксперимент; сейчас он не выполняет критерий надёжной фоновой интеграции.

Экспериментальный код и .app оставлены только в игнорируемых локальных `chelka-lab/native/artifacts/0.4.1/`, вне рабочего приложения и публикуемых исходников. Производственный код возвращён точно к принятому коммиту 0.4.0; повторная release-сборка прошла. Регрессии Apple Music, Chrome, Hover и полки заново не объявляются проверенными: они не изменялись. Playwright, мобильные тесты, захват аудио/экрана и приватный MediaRemote не запускались.
