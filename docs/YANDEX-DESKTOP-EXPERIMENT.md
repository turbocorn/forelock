# Forelock 0.4.1 — эксперимент Yandex Desktop

Локальная экспериментальная сборка для Mac пользователя. Ветка `feature/yandex-desktop-nowplaying` создана от `feature/music-providers` (0.4.0, `12c4dec`). В `main` ничего не переносится. Эта интеграция не принята как постоянная зависимость и не готова к публичному распространению.

## Зависимость и граница процесса

Используется [MediaRemote Adapter](https://github.com/ungive/mediaremote-adapter/tree/0e82bf1c44ec39554fbfc402ec88a48c6ae2a0fd), ровно `0e82bf1c44ec39554fbfc402ec88a48c6ae2a0fd`, BSD-3-Clause. Неизменённые исходники и лицензия находятся в `chelka-lab/native/Vendor/MediaRemoteAdapter/`; `UPSTREAM.json` фиксирует SHA-256 каждого файла. Офлайн-сборщик проверяет хеши и компилирует тот же набор Objective-C файлов, что upstream CMake, плюс собственный `MediaRemote/ForelockHost.m`. Вендор не содержит вложенного Git-репозитория.

Главный Forelock не линкует MediaRemote и не загружает адаптер. Он запускает один прямой дочерний `/usr/bin/perl` с собственным коротким скриптом, который загружает собранный framework из .app. Только внутри дочернего процесса вызывается приватный API. Окружение ограничено; переменные Perl/DYLD не наследуются. Приложение и framework подписаны локально ad-hoc. Entitlements системы и приложений не изменялись; SIP не отключался. LaunchAgent, daemon и постоянно работающая служба не создаются. Захвата экрана/аудио и инъекции в Яндекс нет.

Это приватный API и зависимость от системного Perl/platform binary: обновление macOS может сломать загрузку, символы, метаданные или отправку команд. Изоляция процесса ограничивает последствия сбоя, но не делает API публичным или поддерживаемым Apple. App Store, Developer ID, hardened runtime и notarization этой схемы не проверялись.

## Источник и JSON

`YandexDesktopMusicProvider` использует общую архитектуру MusicProvider и отдельный поток JSONL. Принимается только `ru.yandex.desktop.music`: системный PID, MRClient.bundleIdentifier и bundle ID реально работающего NSRunningApplication должны согласоваться. Источник читается до и после метаданных/playing; смена или неоднозначность очищает снимок. Единственный ID — `yandex-desktop/<pid>`. Apple Music и вкладки Chrome не превращаются во вторые источники через MediaRemote.

Трек, исполнитель, альбом, обложка, playing/paused, длительность и позиция приходят из реального Now Playing. Прогресс интерполируется только при согласованном playing и временной отметке. Пустые/противоречивые данные не заменяются заглушкой. Яндекс появляется только когда именно он подтверждён системным источником; при другом системном плеере он исчезает, даже если процесс Яндекса открыт.

Каждый JSON содержит версию, UUID сессии, поколение состояния и монотонный sequence. Смена источника, трека, playback state или допустимых команд меняет поколение. Поздние ответы предыдущего запуска, повторные сообщения и регресс поколения отвергаются. Команда с одним sourceID без захваченного поколения запрещена.

Лимиты: входящая строка до 1,5 MB; команда до 4 KiB; обложка до 1 MB, максимум 2048 px по стороне и 4 млн пикселей; ограниченные строки и конечные тайминги до 7 суток. Изображения проверяются ImageIO с обеих сторон, ключ UI-обложки учитывает содержимое, а не только размер. Метаданные, изображения и stderr не сохраняются на диск.

## Отправка команд и оставшийся риск

Доступны play, pause, next, previous. Запрет skip из Now Playing выключает next/previous. **Seek не реализован и не предлагается**: для него нужна отдельная живая проверка и согласованное расширение.

Перед отправкой Forelock проверяет актуальный выбранный ID, поколение, возраст подтверждения менее 5 секунд, живой PID, набор команд и отсутствие другой команды в обработке. Helper заново получает согласованное состояние, сравнивает session/generation/PID и ещё раз проверяет MRClient прямо в callback перед глобальным send. Результат подтверждается повторным чтением playback/track/position; отсутствие подтверждения показывается как ошибка.

Управление блокируется при другом системном источнике, закрытом Яндексе, ошибке чтения, истёкшем подтверждении, несовпадении поколения/PID, изменении выбранного плеера или неподдерживаемой команде. Дополнительно **любой свежий playing-снимок Apple Music или Chrome блокирует все команды Яндекса**. Это покрывает случай, когда системный Now Playing оставил приостановленный Яндекс, но браузер уже играет. Пауза/продолжение Chrome по-прежнему адресуются конкретной вкладке через независимый мост.

**Абсолютной защиты от ошибочного адресата нет.** MediaRemote Adapter отправляет команду текущему системному плееру, а не выбранному PID. Между последней проверкой и глобальным send плеер может смениться; атомарной адресации этот API не даёт. Это ограничение постоянно обозначено у выбранного источника и раскрыто в help/accessibility, а также в настройках. Forelock не пытается принудительно назначить Яндекс системным плеером.

## Жизненный цикл

Уведомления ускоряют обновление, но их отсутствие не считается паузой. Каждые 2 секунды helper заново читает источник и состояние. Если 5 секунд нет достоверного подтверждения, снимок становится недоступен и helper перезапускается. Закрытие самого Яндекса проверяется независимо по реально живому процессу.

Неожиданный выход приводит к очистке метаданных и ожидающих команд. Разрешены пять перезапусков с задержками 0,5 / 1 / 2 / 4 / 8 секунд на одно включение. После этого источник отключён до выключения и включения настройки. Последовательный ограниченный reader сохраняет порядок сообщений; старый запуск не может завершить новый из-за поздней ошибки разбора.

Штатный выход Forelock синхронно закрывает stdin и завершает собственного child. Дополнительно EOF и смена PPID останавливают host. Зависший собственный процесс получает SIGKILL спустя секунду после SIGTERM. Отключение эксперимента также останавливает child; Apple Music, Chrome и полка продолжают работать.

## Локальная проверка и откат

Установлено `~/Applications/Forelock.app`, версия 0.4.1 / 41. В настройках есть «Яндекс: MediaRemote (эксперимент)». Сначала откройте Яндекс вручную и запустите трек, затем выберите источник в Forelock. Если играет другой плеер, остановите его через его собственный интерфейс или независимый провайдер. Не считайте переключатель источников Forelock способом принудительно сменить системный Now Playing.

Фактическая матрица и границы проверки — [ACCEPTANCE.md](../chelka-lab/native/ACCEPTANCE.md). История 0.4.0 сохранена в [ACCEPTANCE-0.4.0.md](../chelka-lab/native/ACCEPTANCE-0.4.0.md).

Прежний установленный bundle 0.4.0 сохранён целиком локально в `chelka-lab/native/artifacts/rollback-0.4.0/Forelock.app`. SHA-256 его executable: `306b5a3f85508834eb2db6a89ba19e490433b1d7636ddb7f3a595aafd649ff5d`. Копия не публикуется в Git.

Для отката завершите Forelock через меню, затем из корня репозитория:

```sh
./chelka-lab/native/scripts/rollback-0.4.0.sh
open "$HOME/Applications/Forelock.app"
```

Скрипт проверяет подпись и версию резервного bundle, отказывается работать при запущенном Forelock, переносит экспериментальное .app целиком в уникальный каталог artifacts и возвращает 0.4.0. Это исключает оставшийся framework внутри старой версии. Настройки и файлы полки не очищаются. Если локальной копии нет, исходная 0.4.0 остаётся в `feature/music-providers`; её можно собрать в отдельном checkout без изменения этой ветки.
