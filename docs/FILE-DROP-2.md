# Forelock 0.5 — File Drop 2.0

Экспериментальная ветка `feature/file-drop-2` от актуальной `feature/yandex-desktop-nowplaying` (`98c2061`). Версия .app — 0.5.0 / 50. Рабочая установленная 0.4.1 сохранена целиком локально в `chelka-lab/native/artifacts/rollback-0.4.1/Forelock.app`.

## Жест

Возьмите один или несколько файлов в Finder и ведите к центру верхней части экрана. Достаточно пройти примерно в 150–200 pt ниже камеры: не требуется попадать в аппаратный вырез или несколько верхних пикселей. Когда появится чёрная поверхность с пунктирной границей и «Отпустите файлы», переместите указатель внутрь пунктирной зоны и отпустите.

На текущем экране область обнаружения назначения — **640 × 260 pt** от верхнего центра. Она существует только во время наблюдаемого движения с зажатой левой кнопкой рядом с чёлкой. Видимая поверхность — **520 × 208 pt**, полезная пунктирная зона — **480 × 142 pt**. Ширины адаптируются к дисплею; высоты учитывают реальную высоту камеры. Отпускание в прозрачной области вокруг пунктирного блока не принимается.

После drop показывается копирование, затем результат на 1,25 с; возвращается прежний контекст (Idle, Hover, Обзор, Полка, просмотр или настройки). Навигация в Shelf не навязывается. Оригиналы остаются на месте. При частичной ошибке показано фактическое число добавленных копий; детали доступны на полке. Отмена/отпускание вне цели ничего не импортирует. Пока сессия продолжается, hover timeout не закрывает панель даже после выхода указателя за её границу.

## Механизм

Публичный [NSDraggingDestination](https://developer.apple.com/documentation/appkit/nsdraggingdestination) получает `NSDraggingInfo`, когда AppKit направляет сессию в назначение. Достоверно узнать глобально о файловом drag до этого шага используемый API не позволяет. [Глобальный NSEvent monitor](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html) сообщает движение мыши, не тип переносимых данных.

Поэтому mouseDragged только разрешает временно расширить frame **того же NSPanel** при приближении к чёлке. Отдельного окна нет. Прозрачная часть — область получения нативной сессии; SwiftUI-host остаётся прежнего размера по центру сверху, а чёрный контур расширяется своей прежней SurfaceSpring. Верхний якорь, маска и геометрия камеры не меняются.

Только `sender.draggingPasteboard` внутри реального NSDraggingInfo используется для `.fileURL`, только с разрешённой операцией copy. Ни общий clipboard, ни глобальный named drag pasteboard не опрашиваются. Нефайловые payload не раскрывают поверхность. Собственный drag-out, модальные операции и копирование блокируют входящую сессию. Старая или уже обработанная sequence не может повторно скопировать файлы либо закрыть новую сессию.

Обычное движение/нажатие без drag не расширяет frame. После mouse-up временное расширение убирается; короткая отсрочка до 150 мс нужна только для завершения нативных perform/conclude callbacks, вне видимого контура без нажатой кнопки клики уже проходят. Визуальная поверхность и native hit test пунктирного блока используют один rect. Файловое хранилище, drag-out, музыкальные провайдеры и MediaRemote не изменены.

## Границы

- До входа в назначение временная область включается для **любого** наблюдаемого left-drag рядом с чёлкой: тип файла ещё неизвестен. Это не повод рисовать drop UI; его открывает только файловый NSDraggingInfo. Поведение Chrome tab-drag требует живой проверки.
- Доставка внешних mouseDragged зависит от нативного event stream. Если конкретный источник/версия macOS его не даёт, универсальная ранняя активация не обещается. Запасной публичный путь — предварительно раскрыть Forelock либо использовать существующее «Добавить». Не добавлены event taps, Accessibility/Input Monitoring или частные глобальные drag API.
- Поддержаны существующие файловые URL и несколько файлов. File promises, вложения без готового локального URL, жесты только правой кнопкой, Mission Control/перенос между Spaces и иные дисплеи отдельно не заявляются проверенными.
- Автотест с тестовым NSDraggingInfo проверяет обработку payload и инварианты, но не доказывает удобство физического жеста Finder → панель → Finder. Это остаётся ручным критерием приёмки.

Результаты конкретной сборки — [ACCEPTANCE.md](../chelka-lab/native/ACCEPTANCE.md). Продуктовые направления — [PRODUCT-FOUNDATIONS.md](PRODUCT-FOUNDATIONS.md); Clipboard/Devices/Activities и новый Expanded в этой версии не реализуются.
