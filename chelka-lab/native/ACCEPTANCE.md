# Forelock 0.5 — File Drop 2.0, проверка сборки

8 ноября 2026. Экспериментальная **0.5.0 / 50** собрана и установлена в `~/Applications/Forelock.app` на реальном MacBook / macOS 15.7.3 / Apple Silicon. Ветка `feature/file-drop-2` создана от актуальной `feature/yandex-desktop-nowplaying` (`98c2061`). Слияния в main нет.

**Главный критерий — физический Finder drag через расширенную область — пока не подтверждён пользователем.** Эта сборка готова к ручной проверке, не объявлена принятой по unit-тестам или рендеру. Инструмент native UI открывает состояния приложения, но не выполняет достоверный межоконный системный drag настоящей мышью/трекпадом.

## Что изменилось

Один прежний NSPanel временно получает область назначения 640 × 260 pt (на текущем дисплее), когда замечено внешнее mouseDragged с зажатой левой кнопкой и указатель приближается к верхнему центру. Попасть можно на 150–200 pt ниже камеры. Только файловый NSDraggingInfo раскрывает поверхность 520 × 208 pt с пунктирной целью 480 × 142 pt. До подтверждения payload видимый UI не меняется. Глобальный drag pasteboard не читается.

Отпускание принимается только внутри видимого пунктирного rect, с copy и готовыми файловыми URL. После копирования показан фактический результат на 1,25 с, затем возвращается прежний контекст без перехода в Shelf. Отмена/выход не импортирует файлы. Настоящая сессия удерживает поверхность и при выходе курсора; hover timeout приостановлен. Копирование и неготовность приложения блокируют новую сессию. Повторный perform одной sequence не добавляет файлы снова.

Полный механизм, ограничения public API и запасной путь — [FILE-DROP-2.md](../../docs/FILE-DROP-2.md).

## Проверено автоматически — только новые инварианты

Целевой запуск `swift test --filter FileDropTests` в настоящей WindowServer-сессии: **6 тестов, 0 ошибок, 0 пропусков**. Шесть новых тестов:

1. Обычное нажатие, старый pasteboard или новое нажатие без mouseDragged не включают probe; mouse-up, уход из области, блокировка и отклонение сбрасывают его.
2. Область имеет глубину для входа в 180 pt ниже камеры; верхний центральный якорь и исключённая камера сохраняются.
3. Временный canvas не растягивает нарисованный SwiftUI-host. После отмены расширенный canvas убирается; устаревшая sequence не закрывает текущую. Hover не истекает во время нативной сессии, в том числе при тестовой позиции вне панели.
4. Два тестовых файла копируются один раз через прежний ShelfModel/repository; оригиналы сохраняются. Контексты Idle и Overview сохраняются после отмены и после копирования/подтверждения.
5. Ошибка копирования не выдаётся за успех и не меняет контекст; показан фактический нулевой результат, ошибка остаётся доступна на полке.
6. Тестовый NSDraggingInfo передаёт только собственный session pasteboard. Вне видимой цели drop запрещён, внутри принимаются два file URL; URL вкладки и блокированный собственный drag-out отклоняются.

Это проверки production policy, view callbacks и реальных копий из изолированных fixtures. Тестовый NSDraggingInfo — не системный Finder drag. Внешние пользовательские файлы и глобальный pasteboard тестами не изменяются. Прежний общий набор был случайно запущен скриптом до добавления новых тестов (26 прошли, 2 WindowServer-проверки пропущены в sandbox); он не используется как результат приёмки File Drop 2.0.

## Наблюдалось в установленном .app

- Idle → Hover открыт через доступное AX-действие; музыкальный блок и полка помещаются в прежних размерах. Затем открыт настоящий Expanded и осмотрен снимок установленного окна: музыка и два существующих элемента полки без наложений.
- Реальная десктопная Яндекс Музыка продолжена из Forelock, метаданные/позиция обновлялись; после замены .app и повторного запуска Forelock система продолжила воспроизведение, источник восстановился. Реальная пауза сработала в окончательной установленной сборке. Музыка оставлена на паузе, Forelock — в Idle.
- Существующий файл полки открыт встроенным Quick Look в той же поверхности. Файлы полки не удалялись и не мигрировали; тестовая папка Finder открыта и затем закрыта.
- Drop-view отрисован из production NSHostingView в тестовом контроллере на этом Mac и осмотрен: заголовок, текст и пунктирная граница не обрезаются. Локально: `native/artifacts/0.5/drop-view.png`. Это **рендер тестового состояния**, не снимок реального входящего drag.
- В окончательном Idle реальные bounds WindowServer — **220 × 38 pt, Y=0, слой 26**. Увеличенного скрытого drop-окна в покое нет; второе собственное окно — прежний status item в строке меню.
- React/WebView, мобильные и Playwright-тесты не использовались.

## Ручная приёмка — ожидается

| Сценарий настоящей мышью/трекпадом | Статус 0.5 |
| --- | --- |
| Один файл Finder → широкая область под камерой → пунктирная цель | Ожидается |
| Несколько файлов одним drag | Ожидается |
| Escape и отпускание вне цели без добавления | Ожидается |
| Finder-файл поверх открытого Chrome | Ожидается |
| Клики/перестановка вкладок Chrome без ложного раскрытия | Ожидается |
| Непрерывное открытие и удержание до конца drag | Ожидается; anchor/timeout проверены детерминированно |
| Forelock → Finder, существующий drag-out | Ожидается; его исходники не изменены |
| Физический Hover, переход к кнопкам и фиксация Expanded | Ожидается для 0.5; native состояния осмотрены через AX |
| Непрерывность музыки именно во время настоящего drag | Ожидается; плеер работает, обращения к провайдерам из drop-кода отсутствуют |

Пользователю отправлена короткая инструкция проверить один/несколько файлов на 150–200 pt ниже камеры, отмену и drag-out. До ответа эти строки не помечаются успешными. Подтверждения 0.4.1 находятся в [архиве](ACCEPTANCE-0.4.1.md) и не подменяют проверку нового механизма.

## Сохранённая основа и откат

`ForelockMusic`, MediaRemote host/vendor, MusicCoordinator, MusicViews, NativeFileViews, ShelfModel/ShelfRepository, NotchGeometry и NotchInteraction не изменены относительно 0.4.1. Изменения окна ограничены временным drag canvas, его routing и lifecycle; рамка поверхности, камера, уровень окна и прежняя пружина сохранены. После отпускания кнопки вне видимой поверхности мышь проходит в обычные приложения; постоянного увеличенного невидимого окна нет.

Версия 0.4.1 / 41 целиком сохранена в `native/artifacts/rollback-0.4.1/Forelock.app`, подпись проверена. Окончательная release-сборка 0.5.0 / 50 подписана ad-hoc; `codesign --verify --deep --strict` прошёл, SHA-256 установленного executable совпал с build. Скрипт отката проверен синтаксически; сам откат не выполнялся, чтобы оставить экспериментальную сборку для пользователя.

Для возврата завершите Forelock, выполните `./chelka-lab/native/scripts/rollback-0.4.1.sh` из корня репозитория и снова откройте приложение. Полка и настройки не очищаются.

[PRODUCT-FOUNDATIONS.md](../../docs/PRODUCT-FOUNDATIONS.md) описывает три направления: Clipboard/Shelf, Media, Live Activities. Ни Clipboard Manager, ни Devices, ни общий движок Activities, ни новый Expanded в 0.5 не реализованы.
