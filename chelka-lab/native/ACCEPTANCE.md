# Forelock 0.4.1 — фактическая локальная проверка

8 ноября 2026. Нативная **0.4.1 (41)** собрана из исходников, установлена в `~/Applications/Forelock.app` и запущена на MacBook / macOS 15.7.3 / Apple Silicon, Xcode 16.3 / Swift 6.1. Проверка использовала настоящие музыкальные приложения и установленный Forelock. Это эксперимент для локального использования, не публичный релиз и не принятие MediaRemote как постоянной зависимости.

Ветка `feature/yandex-desktop-nowplaying` создана от `feature/music-providers`, исходная 0.4.0 остаётся доступной. `main` и `v0.3.2-stable` не изменены. Прежний отчёт сохранён в [ACCEPTANCE-0.4.0.md](ACCEPTANCE-0.4.0.md). Архитектура, ограничения и откат — [YANDEX-DESKTOP-EXPERIMENT.md](../../docs/YANDEX-DESKTOP-EXPERIMENT.md).

## Реальное воспроизведение

| Проверка | Наблюдение в установленной 0.4.1 |
| --- | --- |
| Яндекс desktop 5.126.1 на переднем плане | Настоящие трек, исполнитель, альбом, обложка, playing/paused, позиция и длительность; сверены с собственным плеером Яндекса |
| Яндекс в фоне, скрытый | Скрытое состояние независимо подтверждено публичным NSRunningApplication.isHidden; пауза и продолжение из Forelock работают без раскрытия окна Яндекса |
| Яндекс свёрнут | AXMinimized=true независимо подтверждён после сворачивания; из Forelock работают pause/resume и next, метаданные продолжают обновляться |
| Play / Pause | Неоднократно выполнены из Forelock, состояние и прогресс действительно меняются |
| Next | Меняет реальную композицию; меняются название, исполнитель/альбом и обложка |
| Previous | Первое нажатие возвращает текущий трек к началу; повторное вернуло предыдущую композицию. На начале очереди без доступного перехода наблюдалось честное «Яндекс не подтвердил команду», а не ложный успех |
| Прогресс | Продвигается при playing, стоит на паузе, обновляется после перехода; длительность меняется вместе с треком |
| Seek Яндекса | **Выключен** на уровне протокола и UI; не проверялся и не объявляется поддерживаемым |
| Переключение Яндекс → Apple Music | Music.app запущен вручную для теста и воспроизводил настоящий локальный трек; Forelock выбрал Apple Music, Яндекс исчез из меню, дубликата Apple через MediaRemote нет |
| Apple Music regression | Реальные pause/resume выполнены из Forelock через существующий независимый Apple Events provider |
| Переключение Яндекс → Chrome | Настоящий Звук в Chrome воспроизводился и управлялся через существующий Bridge; при выборе Chrome системой Яндекс исчез, helper вернул foreign-source |
| Системный Яндекс paused, Chrome playing | Сценарий воспроизведён: все три кнопки Яндекса выключены, видны «Управление заблокировано» и причина про другой играющий плеер. После паузы Chrome через его Bridge управление Яндексом возвращается |
| Команда Яндексу при чужом системном источнике | Production helper при реально играющем Apple Music отклонил диагностический запрос: ok=false, sent=false (stale-generation). Чужому плееру команда не отправлена |
| Закрытие Яндекса | Процесс действительно завершён через его меню, количество NSRunningApplication=0; источник и его метаданные исчезли, helper сообщает not-running |
| Перезапуск Forelock при закрытых плеерах | Music.app и Яндекс остались закрытыми; helper не открывает музыкальные приложения |
| Повторный запуск Яндекса вручную | После запуска трека источник вернулся с новыми актуальными данными без перезапуска Forelock |

Проверка скрытого/свёрнутого процесса сильнее требования доступности окна AX: интеграция не читает AX-дерево Яндекса. Отдельная расстановка окон с Chrome строго на переднем плане не фиксировалась; фоновая работа, реальное переключение системного источника на Chrome и конфликт при одновременных плеерах проверены отдельно.

Chrome-тест этой итерации выполнен с реально открытым Звуком. Яндекс в Chrome и полный авторизованный режим Звука заново не проверялись; прежние границы проверки этих источников остаются в отчёте 0.4.0. Расширение и его permissions не изменены. Исчезновение закрытой вкладки ранее проверено в 0.4.0; этот сценарий здесь повторно не заявляется.

## Helper и защита состояния

- Ревизия адаптера: `0e82bf1c44ec39554fbfc402ec88a48c6ae2a0fd`. Собран локально из проверенных исходников; SHA-256 каждого vendored-файла зафиксирован в UPSTREAM.json. Только один прямой Perl child принадлежит Forelock. В `otool -L` главного executable MediaRemote отсутствует.
- Диагностический запуск production host дал ready и четыре периодических state за 7 секунд без событий. Заведомо старое поколение отклонено с sent=false. После закрытия stdin процесс завершился кодом 0, stderr пуст. Тишина уведомлений не выдаётся за остановку: heartbeat перечитывает реальный статус раз в 2 секунды.
- Принудительный SIGKILL только подтверждённого собственного helper: новый PID появился примерно через **0,72 с**, главный PID не изменился, источник восстановился.
- Отдельная серия шести намеренных сбоев: наблюдались перезапуски через **0,55 / 1,10 / 2,08 / 4,14 / 8,05 с**. После пятого перезапуска новый child больше не создавался, главный Forelock оставался жив. Выключение/включение настройки восстановило единственный helper и источник.
- Настройка off: MediaRemote child отсутствует; on: один новый дочерний PID. Оба штатных выхода Forelock завершили main и его MediaRemote child; существующий Chrome NativeHost не принимался за процесс плеера и не завершался.
- Перезапуск установленного .app восстановил источник и существующий файл полки. В конце эксперимент включён, Forelock работает в Idle, Яндекс оставлен на паузе; временные диагностические child завершены.

Это короткая проверка жизненного цикла и восстановления, не многочасовой soak test. Доступность приватного API после обновления macOS не гарантируется. Нельзя обещать абсолютное отсутствие команд чужому плееру: между проверкой MRClient и глобальным send остаётся принципиальная гонка. Интерфейс и документация предупреждают об этом; при замеченной неоднозначности команды блокируются.

## Интерфейс и файловая регрессия

Геометрия, пружина, hover policy, hit testing, AppKit drag-in/out, хранилище и восстановление файлов не менялись относительно 0.4.0. В настройках той же поверхности добавлен переключатель эксперимента и объяснение ограничения; музыкальный модуль использует прежние размеры. Осмотрены реальные нативные Expanded, настройки и встроенный Quick Look: обложка, типографика, транспорт, прогресс, предупреждение и полка помещаются без пересечений. Физическая привязка аппаратного выреза не объявляется заново принятой по скриншоту.

Пользователь вручную проверил установленную 0.4.1: **Hover над камерой и переход к кнопкам, фиксация Expanded после ухода курсора, Finder → полка → другая папка Finder**. Ответ: **«Все действия работают»**. После этого исправлена только изоляция поздней ошибки reader от следующего запуска child; геометрия, UI и drag-код не менялись.

Автономно проверены сохранность прежнего файла после перезапуска, его встроенный Quick Look, возврат в обзор и Escape → Idle. Пользовательские файлы не удалялись и не мигрировали. Снимки музыкального интерфейса осмотрены в инструменте без сохранения музыкальных данных на диск. Playwright, мобильные/браузерные тесты интерфейса Forelock и веб-лаборатория не запускались.

## Сборка и автоматические проверки

- Финальный `native/scripts/test.sh`: **28 тестов, 0 ошибок, 0 пропусков**, в реальной macOS-сессии. Проверены прежние geometry/window/hover/storage инварианты и новые framing, источник, freshness, replay/generation, изображения, запрет seek, backoff и конфликт независимых плееров.
- Release build прошёл. Установленный executable совпадает с build по SHA-256; версия 0.4.1 / 41. `codesign --verify --deep --strict` проходит для установленного .app и резервной 0.4.0.
- Исходный app 0.4.0 сохранён целиком в `native/artifacts/rollback-0.4.0/Forelock.app`; инструкция и защитный скрипт отката подготовлены. Сам откат не запускался, чтобы оставить установленную экспериментальную сборку для пользователя.
- Системные файлы/entitlement и SIP не менялись, службы не создавались. Новых разрешений браузеру, Accessibility или захвата экранного/аудиопотока Forelock не добавлено.

Unit-тесты дополняют перечисленные реальные проверки, а не заменяют их. Окончательное принятие экспериментальной зависимости остаётся за пользователем после его тестирования.
