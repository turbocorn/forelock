# Forelock 0.5.6 — Accessory Battery, проверка не завершена

9 ноября 2026. Ветка `feature/accessory-battery` от принятой `aab4517` / `feature/live-surface-polish`. Release 0.5.6 / 56 собрана и установлена в `~/Applications/Forelock.app`. **Не объявляется принятой или полностью проверенной.** Основная принятая 0.5.5 сохранена для отката; [её отчёт](ACCEPTANCE-0.5.5.md) не заменяется новой приёмкой. Merge в main не выполняется.

## Подтверждено на реальном Mac

- AirPods Pro: при подключении L/R 100/100%, позднее 99/98%. macOS Bluetooth показала сначала 100%, затем 98%. Живой IOBluetooth адрес наушников точно совпал с соответствующей записью profiler. В первоначально установленной 0.5.6 Workspace действительно показал L 99% / R 98%, закреплённый Ambient — 98% как минимум L/R.
- Magic Mouse: 24% из IORegistry; совпало с системным Bluetooth UI и с точным адресом подтверждённого соединения. Отдельного процента мыши в profiler нет. Итоговый native-тест также получил 24% за 0,18 s полного прохода.
- Кейс: profiler возвращает 74% в другой записи с другим адресом. Проверенной связи с наушниками нет; поле не используется в Forelock. По похожему имени не объединяется.
- После физического отключения AirPods пользователь ответил «Отключены», macOS показала отсутствие соединения. Profiler сохранил старые проценты — это воспроизведённый кэш, а не живой источник подключения. После ответа «Снова подключены» L/R снова связались с правильным live-устройством.
- В первоначальной установленной 0.5.6 дополнительно выполнено отключение через macOS: AirPods исчезли из Workspace, выбранный процент исчез из Ambient, мышь осталась. Подключение восстановило системный аудиовыход. Изначально показался прежний route Stretch без процента; исправлена типизированная передача заряда именно этому существующему событию.
- Пользователь на вопрос о Hover/Expanded и Finder → Mini Shelf → group drag-out ответил **«Всё работает»**. Музыкальные данные и существующая команда продолжения наблюдались в установленной сборке. Исходники провайдеров/MediaRemote не изменены.

## Почему финальная проверка остаётся открытой

На одной из переустановок обнаружена блокировка синхронного IOBluetooth bootstrap на main. Затем выявлена петля: registration немедленно сообщала об уже подключённой мыши, отменяла собственный baseline и запускала новую регистрацию. Оба случая сохранены в локальных профилях/проваленном промежуточном тесте; не скрываются успешным итогом unit-тестов.

Первая регистрация перенесена с main и отложена до публичного CoreBluetooth callback готовности. Начальные connect-уведомления до установки token больше не отменяют baseline. Итоговый отдельный аппаратный тест завершился с мышью 24%, итоговые 49 тестов прошли. Исключение из запрета трогать старый AudioDeviceMonitor ограничено этим необходимым исправлением инициализации/регистрации.

**В конечном установленном .app** запуск и Workspace отзывчивы, но Bluetooth остаётся в «Ожидание данных Bluetooth». В журнале наблюдался незавершённый TCC request. Системный список разрешений показывает Forelock enabled, однако это не доказывает завершённую авторизацию данного переустановленного бинарника. Инструмент CUA запретил доступ к UserNotificationCenter по своим правилам безопасности. Пользователю отправлен запрос проверить/разрешить системный диалог. Никаких сбросов TCC, переключения защиты или обхода запрета не выполнялось.

До завершения этого шага **не подтверждены на конечном .app**: реальный Stretch с процентом, повторная аппаратная проверка после последнего перезапуска и долгий ресурсный замер активного монитора. При неизвестной готовности приложение не изображает старые AirPods-проценты текущими. Это не финальная приёмка 0.5.6.

## Проверки и ресурсы

Итоговый целевой запуск: AccessoryBatteryTests, DeviceEventTests, LiveSurfaceTests, LiveSurfacePolishTests, PanelIntegrationTests — **49 тестов, 0 ошибок, 0 пропусков**, из них 14 новых. Лог: `artifacts/0.5.6/native-regression-final.log`. Проверены нули/неизвестные значения, строгая идентичность, неподходящий кейс, неоднозначные записи, конфликтующие источники, до/после соединения, TTL, opt-in, типизированный payload без парсинга имени, timeout/oversize/cancel дочернего процесса, native lifecycle. Это не доказательство готовности последнего установленного .app или визуальная приёмка.

Profiler на этом Mac: около 0,07–0,09 s wall, 0,03–0,04 s CPU; IORegistry около 0,01 s wall. Полный нативный проход 0,16–0,33 s. Production-период — 60 s только при наличии устройств, stdout до 2 MiB, timeout каждого процесса 6 s, TTL данных 90 s. Оценка командного CPU при таком интервале — меньше 0,1% одного ядра; это не измерение CPU всего Forelock. Постоянные диагностические capture-процессы не создавались; короткие серии завершены.

Реальные локальные снимки первоначальной установленной 0.5.6: [Ambient с зарядом AirPods](artifacts/0.5.6/ambient-airpods-top.png), [само окно](artifacts/0.5.6/ambient-airpods-real.png). Снимок не выдаётся за финальную проверку после последнего изменения bootstrap. Все raw snapshots, идентификаторы, профили и captures исключены из Git. В опубликованном отчёте нет реальных адресов/серийных номеров.
