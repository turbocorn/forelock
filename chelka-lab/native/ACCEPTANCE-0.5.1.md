# Forelock 0.5.1 — мини-полка после File Drop

8 ноября 2026. Нативная **0.5.1 / 51** собрана, установлена в `~/Applications/Forelock.app` и запущена на реальном MacBook / macOS 15.7.3 / Apple Silicon. Ветка `feature/drop-mini-shelf` — от `feature/file-drop-2` (`6ba8093`). Main и исходная ветка File Drop 2.0 не изменены. Прежний отчёт: [ACCEPTANCE-0.5.0.md](ACCEPTANCE-0.5.0.md).

## Поведение

После импорта та же поверхность 520 × 208 pt превращается в мини-полку с реальными ShelfItem последнего импорта. До четырёх карточек; для большего результата — три и +N. В ней нет отдельного хранилища: сохраняются ID новых элементов, число попыток и ошибка, а миниатюры/названия/URL берутся из ShelfModel.

Существующие NativeFileTile и DraggableFileView обеспечивают нажатие и copy drag-out. Нажатие открывает прежний EmbeddedQuickLook, а «К добавленным», «Назад» и Escape возвращают тот же результат. «Все файлы» и +N открывают полную закреплённую Shelf. Выход курсора из мини-полки на 0,8 с восстанавливает прежний закреплённый экран либо Idle; наведение, нажатие, drag-out и взаимодействие отменяют дедлайн. Есть явный возврат стрелкой; крестик явно закрывает Forelock.

При частичном импорте показано фактическое N из M, только успешные копии и ошибка. Две строки ошибки видны, полный текст доступен через tooltip/accessibility. При полном отказе показана ошибка без выдуманных файлов. Подробности: [MINI-SHELF.md](../../docs/MINI-SHELF.md).

## Реальная ручная проверка

После установки пользователю предложен сквозной сценарий: Finder → drop нескольких файлов → удержание мини-полки курсором → карточка / Quick Look → «К добавленным» → drag-out в Finder; отдельно «Все файлы» → закреплённая Shelf. Ответ пользователя: **«да збс»**. Это прямое ручное подтверждение перечисленного сценария, не результат unit-теста.

Дополнительно в собственных логах установленной 0.5.1 наблюдались настоящие `native-file-drag-enter`, `native-file-drop-committed`, `native-file-drag-end` и переход `file-drop-result` в `miniShelf` с курсором внутри поверхности. При следующем настоящем drag осмотрен нативный блок «Отпустите файлы» для трёх файлов; после ручной проверки осмотрено возвращение в Idle. Музыкальные данные и пользовательские файлы для отчёта на диск не копировались.

| Сценарий | Основание |
| --- | --- |
| Настоящий Finder drop → мини-полка | Подтверждение пользователя + production события NSDraggingInfo |
| Удержание под курсором | Подтверждение пользователя; детерминированно проверено отсутствие общего срока жизни |
| Карточка → Quick Look → мини-полка | Подтверждение пользователя; отдельно проверен реальный QLPreviewView с URL сохранённой копии |
| Мини-полка → другое окно Finder | Подтверждение пользователя; сам инструмент системный drag-out не воспроизводит |
| «Все файлы» → закреплённая Shelf | Подтверждение пользователя + state/pointer тест |
| Задержка 0,8 с, отмена закрытия при возврате/drag-out | Детерминированные тесты production policy и реального контроллера с тестовыми позициями |
| Только последние файлы и +N | Реальные тестовые копии, проверка ID/порядка/количества и нативный рендер для пяти файлов |
| Частичный успех / полный отказ | Реальные копии + недоступные fixture URL; проверены фактические количества и ошибки. Такой отказ настоящим Finder отдельно не воспроизводился |

## Нативная и визуальная проверка

В установленном .app открыты Hover и Expanded: настоящий Яндекс показывал playing, обложку и изменяющийся прогресс, существующая полка содержала семь прежних элементов до ручных тестов. Провайдеры не запускались заново для сценария, музыка продолжала воспроизводиться после обновления.

Инструментальная попытка нажать нативную файловую плитку установленного .app завершилась сворачиванием; она не записана как успешный Quick Look. Сквозной просмотр и drag-out затем отдельно подтвердил пользователь настоящей мышью. Детерминированный тест проверил существующий QLPreviewView и URL копии независимо от этой попытки.

Нативные production views отрисованы в тестовом контроллере на этом Mac с изолированными реальными файлами: `native/artifacts/0.5.1/mini-overflow.png`, `mini-partial.png`, `quick-look.png`, `all-files.png`. Это рендеры тестовых состояний, не снимки физического Finder drag. Осмотрены три карточки +2, имена, существующий Quick Look и частичный результат. Исправлено сжатие ошибки в одну строку; повторный рендер показал две строки без обрезания снизу. Новых окон файлового интерфейса, веб-прототипов или браузерных тестов нет.

## Автоматические проверки

Финальный целевой запуск `swift test --filter 'MiniShelfTests|FileDropTests'`: **11 тестов, 0 ошибок, 0 пропусков** в настоящей WindowServer-сессии.

- Прежние шесть File Drop тестов сохранены; ожидание результата обновлено с исчезающего счётчика на мини-полку. Проверены probe, настоящий session pasteboard в callback, copy, однократный commit, usable rect, отмена и фактические копии.
- Пять новых MiniShelf тестов проверяют дедлайн без фиксированного TTL, удержание при нажатии/drag-out, отмену дедлайна повторным входом, новый batch, только последние ID, границу четырёх файлов / +N, частичный результат, сохранность оригиналов, возврат из Quick Look, прежнюю закреплённую Shelf и существующий native drag source с URL реальных копий.
- Повторный тестовый прогон выявил двойной `stop` в очистке тестового окна и упал при освобождении event monitor. Повторная очистка убрана из теста; финальный прогон выше завершился нормально. Производственный Quick Look и native drag source из-за этого не изменялись.

Release build прошёл; установленный executable совпадает с build побайтно. Версия 0.5.1 / 51 и подпись `codesign --verify --deep --strict` проверены. У главного процесса один принадлежащий ему MediaRemote child. В окончательном Idle WindowServer показывает прежние 220 × 38 pt при Y=0, слой 26; дополнительного файлового окна нет.

## Сохранённая основа и откат

Без изменений относительно 0.5.0: музыкальные провайдеры/координатор/представления, MediaRemote host/vendor, ShelfModel и ShelfRepository, NativeFileViews/EmbeddedQuickLook/DraggableFileView, DropHostingView, FileDragProbe/FileDropLayout, NotchGeometry/SurfaceSpring и обычный NotchPointerPolicy. В контроллер добавлена только отдельная policy для результата импорта; она не меняет hover activation/retention.

Предыдущий установленный bundle 0.5.0 сохранён целиком в `native/artifacts/rollback-0.5.0/Forelock.app`, подпись проверена. Для возврата завершите Forelock, из корня репозитория выполните `./chelka-lab/native/scripts/rollback-0.5.0.sh` и снова откройте приложение. Скрипт проверен синтаксически; сам откат не выполнялся, чтобы оставить пользователю 0.5.1. Полка не очищается, формат хранения не меняется.
